    55→### 3. CRITICAL ARCHITECTURAL CONCEPT — UNDERSTAND THIS FIRST
    56→
    57→**There is no permanent admin computer, teacher computer, student computer, or central school server.**
    58→
    59→Every installed desktop application is an independent peer.
    60→
    61→Each computer:
    62→
    63→1. Has its own local database.
    64→2. Can function independently.
    65→3. Can store its own and authorized replicated data.
    66→4. Can discover and communicate with other installed computers.
    67→5. Can initiate authorized synchronization.
    68→6. Can receive data from other computers.
    69→7. Can maintain pending transfers when another computer is unavailable.
    70→8. Can participate in the examination process regardless of which user previously used it.
    71→9. Can serve other computers while also requesting data from them.
    72→10. Can retain data even after the sending computer disconnects.
    73→
    74→**The currently authenticated user determines the application's available functions.**
    75→
    76→Examples:
    77→
    78→- An administrator logging into Computer A gets the administrator interface.
    79→- A teacher logging into Computer A gets the teacher interface.
    80→- A student logging into Computer A gets the student interface.
    81→- Computer A does not permanently become an administrator, teacher, or student computer.
    82→- Another computer can independently perform the same functions when an appropriately authorized user logs in.
    83→
    84→The prototype must make this distinction obvious.
    85→
    86→A school computer is a technical peer. A user is a person with permissions. An active session joins a user to a computer temporarily.
    87→
    88→Do not design a master-server/slave-client architecture.
    89→
    90→Any authorized peer may distribute approved examinations or collect results. A computer participating in an examination must not depend permanently on another computer to remain operational.
    91→
    92→For the prototype, simulate each computer's independent local data and synchronization states.
